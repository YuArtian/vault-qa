# v1 学习总结 · 关键词检索问答

> 对应 git tag：`v1` ·时间：2026-07
> 本项目是「项目驱动学 AI 应用开发」的教学载体：每个版本解决一个真实需求、引入一组知识，每阶段一篇总结。
> 学习者画像：熟悉 JS/TS 的前端工程师，零 Python / AI 基础。

## TL;DR

**用约 100 行 Python 做出第一个能日常使用的 AI 应用**：读 Obsidian 知识库的 88 篇笔记、挑相关的塞进 Prompt、流式输出带出处的回答。启动前只学了 5 项「最小必备知识」（约 3 个碎片日），其余知识全部是做的过程中被 bug 逼出来的——踩了 5 个真实的坑，并开始积累「关键词检索不靠谱」的证据，那是 v3 换向量检索的入场券。

## 1. 做出了什么

三个文件，各管一段：

```mermaid
flowchart LR
    A["用户问题"] --> B["vault.py<br/>关键词打分挑笔记<br/>（传统代码）"]
    B --> C["main.py<br/>拼 System Prompt<br/>（传统代码）"]
    C --> D["llm.py<br/>调用 LLM<br/>（唯一的 AI 环节）"]
    D --> E["流式输出<br/>带出处的回答"]
```

实测亮点：问「js 的装饰器是什么」，它诚实回答「笔记里没写」并说明笔记只讲了 Python 装饰器——System Prompt 里「禁止编造 + 标注出处」的约束真实生效。

后端可切换：默认走 Claude Agent SDK（复用本机 Claude Code 登录，零 key），一个环境变量切到任意 OpenAI 兼容服务商——顺手实践了「多 Provider 适配器」模式的最小版。

## 2. 第一次实战用上的 Python 知识

启动前的最小必备只有：uv、对照 JS 的语法直觉、async 四个关键字、Pydantic 当 Zod 用、调通一次 LLM API。下面这些是写代码时现学现用的：

| 知识点 | 用在哪 |
|--------|--------|
| uv 工程化（init / add / run / lock） | 建项目、管依赖 |
| `pathlib.rglob` + `read_text` | 一次读入 88 篇笔记 |
| 列表推导式（含双重 for）、切片滑窗 | 中文两字滑窗切词 |
| 正则 `findall`、字符区间 `[一-鿿]` | 中英文关键词提取 |
| `async def` / `await` / `asyncio.run` / async 生成器 | 整条流式输出链路 |
| `os.environ` + `load_dotenv` | 全部配置 |
| `try/except (EOFError, KeyboardInterrupt)` | Ctrl+C 优雅退出 |
| f-string、元组成员检测 `in`、空串真值判断 | 问答循环 |

## 3. 第一次实战用上的 AI 知识

- **System Prompt 约束设计**：角色设定 + 三条规则（只根据笔记回答 / 没写就说没写 / 标注出处）。体会：**约束比能力难得**——不加约束模型一定会热情地编
- **上下文预算意识**：`limit_chars=24000`，不能把整个知识库塞给模型——上下文窗口是硬约束
- **Agent 公式的反向理解**：`allowed_tools=[]` + `max_turns=1` 把 Claude Code 这个 Agent 降级成一次普通 LLM 调用 → 反过来即 **Agent = LLM + 工具 + 循环**，v6 就是把这两个开关重新打开
- **AI 应用的真相**：100 行代码里 AI 调用不到 10 行。AI 应用 ≈ 90% 传统工程 + 10% 模型调用，工程师的价值在调用的前（喂什么）、中（怎么约束）、后（怎么验收）

## 4. 踩过的坑（最值钱的部分）

| # | 坑 | 现象 | 修法 | 学到的 |
|---|----|------|------|--------|
| 1 | 中文没有空格分词 | `split()` 切不出「装饰器」，挑错笔记 | 两字滑窗 | 中英文文本处理的根本差异 |
| 2 | 常见词霸榜 | 「Python」每篇都有，满篇 Python 的笔记总分最高 | IDF 权重（越常见的词越不值钱） | 亲手发明了检索技术的核心直觉 |
| 3 | 子串匹配噪音 | `js` 命中 json / Next.js，无关笔记混进参考列表 | `\b` 单词边界 + 忽略大小写（留作练习） | 短词子串匹配不可靠 |
| 4 | 模块顶层读环境变量 | import 发生在 `load_dotenv()` 之前，`.env` 不生效 | 挪进函数内读 | 顶层代码在 import 瞬间执行 |
| 5 | git add/add 冲突 | 本地 README 与远程自动生成的 README 相撞 | `checkout --ours` 后完成合并 | 无关历史合并与冲突取舍 |

## 5. 认知升级

- **项目驱动被验证了**：最小必备五项三个碎片日落地，直接产出能用的东西；换成线性学习这是一周以上的量
- **知识是被项目「需要」出来的**：IDF、滑窗、import 时机——没有一个是「按大纲学到的」，全是被 bug 逼出来的，所以记得牢
